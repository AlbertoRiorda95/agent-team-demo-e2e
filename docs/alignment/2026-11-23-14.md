## What changed
`services/api` implements the real `POST /launches` of
`docs/design/launch-intake.md`: KV window `launch_window`, config snapshot,
`LaunchAccepted` on `launches.accepted` with the ack, 503 on bus failure,
`status.api` heartbeat. `docs/api/openapi.yaml` and `proto/` are unchanged.

## What the others relied on (before → after)
- Environment: new `LAUNCH_WINDOW_S` (seconds, default 300, for tests only).
  Compose and Kubernetes need not set it; leave it unset in production.
- NATS objects: the api creates the KV bucket `launch_window` (stream
  `KV_launch_window`, TTL 300 s, history 1) itself, at start-up and again after
  a reconnection, as the spec says; it creates or edits none of the four
  streams of `proto/nats/streams/` (`nats-init`, #33). It needs `LAUNCHES` to
  answer 202 (without it: 503) and reads `CONFIG` if present.
- Generated code: the api's Python code of `proto/trajectory/` is committed
  in `services/api/src/trajectory/v1/` (as `libs/trajectory-proto/src/gen`),
  generated with `services/api/buf.gen.yaml`. The Dockerfile and the CI `api`
  job need no change (checked: `docker build -f services/api/Dockerfile .`
  imports it). Suggested for the `proto` job (it has `npm ci` and buf.build):
  `services/api/scripts/generate-proto.sh --check`, which fails when a change
  to `proto/trajectory/` was not regenerated for the api.
- CI `api` job: `uv run pytest` now also runs integration tests that start a
  NATS container with testcontainers (Docker, as on `ubuntu-latest`; image
  `nats:2-alpine` pinned as in `compose.yml`, plus testcontainers' Ryuk
  reaper). About 25 s more.
- Logs: one JSON line per request from the app (`event: request`); uvicorn's
  access log is off.
