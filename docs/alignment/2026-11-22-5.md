## What changed
`services/propagator/` exists: a Conan 2 + CMake project (`CMakePresets.json`
preset `release`), the `propagator_core` library, the `propagator` executable
and a GoogleTest smoke test.

## What the others relied on (before → after)
Nothing existed before; this is the start-up interface that foundations row 11
(Dockerfile, compose) builds on:
- Build: `conan install . --build=missing -s compiler.cppstd=20`, then
  `cmake --preset release && cmake --build --preset release`; the binary is
  `build/Release/propagator` (`cmake --install build/Release` puts it in
  `bin/`). cnats is linked statically and built without TLS (no OpenSSL).
- Configuration: `NATS_URL` only (default `nats://localhost:4222`). No port,
  no new environment variable.
- Logs: one JSON object per line on stderr
  (`{"level":...,"service":"propagator","msg":...}`); credentials in
  `NATS_URL` are redacted.
- NATS down at start-up: logs `"cannot connect to NATS"` with
  `"health":"degraded"` and retries with backoff (0.5 s doubling up to 30 s);
  it never crashes. Once connected, the client reconnects on its own.
- Stops cleanly (exit 0) on SIGTERM or SIGINT.
- **No health endpoint.** The propagator has no HTTP server (the spec's Reuse
  names no HTTP library for it); its health is internal
  (`NatsConnection::health()`). The foundations criterion "docker compose ps
  shows all healthy" and the error case "health check answers degraded (503)"
  need a decision for this service: a process-liveness healthcheck in the
  Dockerfile, or a probe mechanism (an HTTP library or a health file) added in
  a backend task. Designer to decide.
