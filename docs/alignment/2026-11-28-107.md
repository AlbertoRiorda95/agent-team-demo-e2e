## What changed
The viz-web server serves the stored history (docs/design/viewer.md, task 3):
`GET /api/launches` (keyset pages) and `GET /api/launches/{id}/trajectory`,
read from PostgreSQL as the read-only user, in the tables of the prefix from
the latest `config.store.applied`. Contract: `services/viz-web/server/openapi.yaml` 0.3.0.

## What the others relied on (before → after)
- Routes: none → `GET /api/launches?limit=1..200 (default 50)&cursor=<opaque>`
  answering `{ items: LaunchSummary[], next_cursor: string | null }`, newest
  first; `GET /api/launches/{id}/trajectory` answering the same
  `TrajectoryComputed` proto3 JSON as the live event (decode with `fromJson`).
  Errors `application/problem+json` (`type`, `title`, `status`, `detail`):
  400 bad limit / cursor / id, 404 unknown id, 503 PostgreSQL unreachable or
  not configured.
- Environment of the viz-web server: `DATABASE_URL`
  (`postgresql://<host>[:<port>]/<database>`, no credentials in it),
  `DATABASE_USER`, `DATABASE_PASSWORD` (the `viz_web` user's values). Unset
  `DATABASE_URL`: the server starts and the history answers 503. `DATABASE_URL`
  set without user or password: the server refuses to start.
- NATS: a third ordered consumer, on `config.store.applied` (stream `CONFIG`,
  deliver "last per subject"). `/healthz` answers 503 while it is not
  consuming, as for the two other subscriptions (compose's `nats-init` already
  creates `CONFIG`). PostgreSQL is not part of `/healthz`.
- New runtime dependency: `pg` 8.23.1 (in the lockfile; the image's
  `npm ci -w services/viz-web/server` installs it). The image's start-up
  break of `2026-11-23-15.md` is unchanged by this branch.
