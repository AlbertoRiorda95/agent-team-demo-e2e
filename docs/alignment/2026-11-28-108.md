## What changed
Task 4 of docs/design/viewer.md. Compose has a new one-shot `db-init` service
that creates the read-only login `viz_web` (member of `trajectory_reader`).
The viz-web service gets `NATS_URL` and `DATABASE_*` and waits for `nats-init`
and `db-init`. The viz-web image now builds `libs/trajectory-proto` and the UI
and ships them.

## What the others relied on (before → after)
- Environment (everyone running compose): `.env` had no viz-web database
  password → it needs `VIZ_WEB_DB_PASSWORD` (see `.env.example`). Without it,
  `docker compose` stops with "set VIZ_WEB_DB_PASSWORD in .env".
- backend (viz-web server, task 3): in compose the server gets
  `DATABASE_URL=postgresql://postgres:5432/${POSTGRES_DB}`,
  `DATABASE_USER=viz_web`, `DATABASE_PASSWORD=${VIZ_WEB_DB_PASSWORD}` and
  `NATS_URL=nats://nats:4222`. `viz_web` has LOGIN and INHERIT, nothing else.
  It reads the tables through `trajectory_reader`: SELECT on
  `<prefix>launches` and `<prefix>trajectory_samples`, granted by store's V3.
  It cannot CREATE in `public`, because PostgreSQL 17 does not allow that by
  default. I checked in compose that SELECT works and that INSERT and DELETE
  get "permission denied".
- db-init creates `trajectory_reader` too when it is missing. It does the same
  thing as V3, so db-init and store can run in either order. db-init sets the
  password again on every run, so if you change `VIZ_WEB_DB_PASSWORD` and run
  `docker compose up`, the new password is used.
- viz-web image (backend and frontend): the server could not start
  (`ERR_MODULE_NOT_FOUND`, entry 2026-11-23-15) and had no `dist/` (entry
  2026-11-28-106). Now `libs/trajectory-proto/dist` (built with tsc from the
  committed `src/gen/`, no buf in the image) and `services/viz-web/dist` (built
  with `npm run build -w @agent-team-demo-e2e/viz-web`) are in the image. The
  UI build only gets what `services/viz-web/Dockerfile.dockerignore` lets
  through: `index.html`, `vite.config.ts`, `tsconfig.json`, `src/`,
  `packages/ui-tokens/` and `libs/trajectory-proto`. If frontend adds a
  `public/` folder or another config file, or uses a new workspace, the
  dockerignore and the `COPY` lines need a devops change.
- Covers the devops items of entries 2026-11-23-15 (Dockerfile, dockerignore,
  compose `NATS_URL` + `nats-init`) and 2026-11-28-106 (UI in the image). The
  Kubernetes probe item of 2026-11-23-15 is still open for M6.
