## What changed
The viz-web server skeleton exists in `services/viz-web/server/` as its own
private npm package `@trajectory/viz-web-server` (Fastify, `GET /healthz`,
`server/openapi.yaml`, Vitest tests). It is not yet an npm workspace: the
root `package.json` (devops) and `services/viz-web/package.json` (frontend,
task 9) are outside backend's boundary, so nothing installs or tests it in
`npm ci` / `npm test` / the CI `web` job until the follow-up below.

## What the others relied on (before → after)
Nothing existed before; this is the interface:
- Package: `services/viz-web/server/package.json`, scripts `start`
  (`node src/main.ts`, Node 24 type stripping, no build step), `test`
  (`vitest run`), `typecheck` (`tsc -p tsconfig.json`). Its `tsconfig.json`
  extends `../../../tsconfig.base.json`.
- Proposed (devops): add `services/viz-web/server` to the root `workspaces`
  and regenerate `package-lock.json`. Verified locally: with that entry,
  `npm install`, `npm test -w services/viz-web/server`, `npm run typecheck
  -w services/viz-web/server` and root `npm test` pass. The same layout is
  meant for `services/control-web/server` (foundations row 8).
- Environment: `VIZ_WEB_SERVER_HOST` (default `127.0.0.1`; set `0.0.0.0` in a
  container) and `VIZ_WEB_SERVER_PORT` (default `3001`), `LOG_LEVEL`
  (default `info`). Not in `.env.example` yet (devops). Logs are JSON (pino).
- `GET /healthz`: 200 `{"status":"ok"}`; 503 `{"status":"degraded"}` when a
  dependency check fails (no checks in the skeleton; NATS and PostgreSQL
  come with M1/M3). Usable as the container healthcheck (task 11).
- Frontend: the Vite dev server (port 5173) can proxy `/api` and `/healthz`
  to `localhost:3001`; nothing requires it yet.
