## What changed
`services/api` exists: a uv project (Python 3.12, `pyproject.toml` +
`uv.lock`, package `src/trajectory_api`) serving `GET /healthz` and the
placeholder `POST /launches` of `docs/api/openapi.yaml`. The contract itself
is unchanged.

## What the others relied on (before → after)
Nothing existed before; this is the interface devops's Dockerfile and compose
task (#11 in `docs/design/foundations.md`) uses:
- Install: `uv sync --frozen` (add `--no-dev` in the image); run:
  `uv run --no-dev trajectory-api` (or `python -m trajectory_api.main` in the venv).
- Environment: `NATS_URL` (existing; without it the api runs and stays
  `degraded`), `API_PORT` (existing, default 8000) and **new** `API_HOST`
  (bind address, default `127.0.0.1`: the container must set `0.0.0.0`).
- Health: `GET /healthz` 200 `{"status":"ok"}` when connected to NATS, 503
  `{"status":"degraded"}` otherwise; the process never exits because NATS is
  down (retries with backoff, nats-py reconnects). A container healthcheck
  can use it (no curl in a slim Python image: `python -c` with `urllib`).
- Logs: one JSON object per line on stdout (uvicorn's too).
- The tests read `docs/api/openapi.yaml` (contract test): the CI `api` job's
  path filter (`.github/workflows/ci.yml`, `changes` job) does not list
  `^docs/api/`, so a contract change alone does not re-run them. Suggest adding it.
