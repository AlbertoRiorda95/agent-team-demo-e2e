## What changed
The control-web server skeleton exists (`services/control-web/server/`,
`GET /healthz`, `server/openapi.yaml`). Since foundations row 8 runs before
row 10, backend also created the workspace manifest
`services/control-web/package.json`, which frontend owns from now on.

## What the others relied on (before → after)
- `services/control-web/package.json`: did not exist → exists, name
  `@agent-team-demo-e2e/control-web`, dependency `fastify`, dev dependencies
  `vitest`, `@types/node`. Scripts: `test` → `npm run test:server`,
  `typecheck` → `npm run typecheck:server`, `start:server` (runs
  `server/src/main.ts` with Node 24 type stripping, no build step).
  Frontend (row 10): keep the `*:server` scripts and chain them into `test`
  and `typecheck` next to the UI ones (for example
  `"test": "vitest run && npm run test:server"`); add `build` for the UI.
  The UI's Vitest config must not pick up `server/` (the server has its own
  `server/vitest.config.ts`).
- TypeScript: the server has its own `server/tsconfig.json` (NodeNext,
  `.ts` import extensions, `types: ["node"]`); the UI's `tsconfig.json`
  should exclude `server/`.
- Port: the server listens on `CONTROL_WEB_PORT` (default 5174, all
  interfaces), the variable of `.env.example`; no new variable. In local dev
  the Vite UI (`npm run dev`, port 5174) and the server collide on the same
  port: frontend's dev setup should run Vite elsewhere or proxy `/healthz`
  and `/api` to the server, and devops points the container's port and
  healthcheck at `GET /healthz` on `CONTROL_WEB_PORT`.
- Container start command (devops, row 11):
  `npm run start:server -w services/control-web` or
  `node services/control-web/server/src/main.ts`; logs are JSON lines on
  stdout; SIGTERM closes the server and exits 0.
