## What changed
The Protobuf toolchain exists: root `buf.yaml` and `buf.gen.yaml`, the
placeholder message `demo.v1.Ping` in `proto/demo/v1/ping.proto`, and the
package `@albertoriorda95/trajectory-proto` 0.0.0 in `libs/trajectory-proto/`
built from the generated TypeScript.

## What the others relied on (before → after)
Nothing existed before; this is the interface the next tasks use:
- `npx buf generate` (repository root) writes `gen/python`, `gen/cpp`,
  `gen/java`, `gen/ts` (ignored by Git). Python, C++ and Java use buf remote
  plugins pinned to protobuf v33.1: generating needs network access to
  buf.build, and each service links the protobuf runtime of that version
  (backend tasks #4-#6 and the api task).
- `libs/trajectory-proto`: `npm run build` (generate + `tsc` to `dist/`), no
  network needed (local `protoc-gen-es` 2.17.0). Entry point
  `@albertoriorda95/trajectory-proto` exports each message type and its schema
  (`Ping`, `PingSchema`), used with `create`/`toBinary`/`fromBinary` of
  `@bufbuild/protobuf` 2.17.0 (a dependency of the package). Web apps add it
  as a workspace dependency (`"@albertoriorda95/trajectory-proto": "0.0.0"`)
  and the package must be built (`npm run build`) before they type-check
  against it: the root `npm run build` builds every workspace, in the order of
  the root `workspaces` list (`libs/` comes after the web apps there).
- `libs/trajectory-proto/src/gen/` is committed (the `reference-docs` job runs
  typedoc on `src/` without building); the package's `npm test` fails when it
  is not in step with `proto/`.
- `/gen/` added to the root `.gitignore`.
