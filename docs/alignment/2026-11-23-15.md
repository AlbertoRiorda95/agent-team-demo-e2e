## What changed
The viz-web server records the launches accepted on NATS
(docs/design/viz-backend.md): an ordered JetStream consumer on
`launches.accepted` (deliver all, stream found by subject), an in-memory record
(latest 1000, dedupe by launch_id), the new route `GET /api/accepted-launches`,
`PipelineError`s on `pipeline.errors`, a `status.viz-web` heartbeat every 5 s,
and `/healthz` tied to the subscription. `server/openapi.yaml` is 0.1.0.

## What the others relied on (before → after)
- Runtime dependency (devops, `services/viz-web/Dockerfile`): the server had
  only `fastify` → it now imports `@albertoriorda95/trajectory-proto`, the
  workspace `libs/trajectory-proto`, whose `dist/` is built by
  `npm run build -w libs/trajectory-proto` (needs `@bufbuild/buf` and
  `@bufbuild/protoc-gen-es`, dev dependencies, plus `proto/` and `buf.yaml`).
  `npm ci -w services/viz-web/server` installs it as a symlink to
  `../../libs/trajectory-proto`, which the image does not copy: the current
  image builds and scans fine but exits at start with `ERR_MODULE_NOT_FOUND`
  (checked with `docker build` + `docker run` on this branch). The image needs
  the built `libs/trajectory-proto` (`package.json` and `dist/`) at
  `/app/libs/trajectory-proto`, for example built in a build stage.
- Environment (devops: compose, `deploy/k8s/`, `.env.example`): new
  `NATS_URL` for viz-web (same name and form as the other services,
  `nats://nats:4222`). Unset → the server starts, logs an error and stays
  `degraded` (503 on `/healthz`).
- NATS (devops): the `LAUNCHES` and `ERRORS` streams of `proto/nats/streams/`
  must exist (nats-init); until `LAUNCHES` exists the server retries with a
  backoff and `/healthz` answers 503. A NATS outage now makes `/healthz`
  answer 503: the liveness probe must tolerate it (or be relaxed) so that the
  pod is not restarted for a NATS outage (spec: `/healthz` is plain liveness,
  503 `degraded` without NATS).
- Frontend: new route `GET /api/accepted-launches` (array, newest first, at
  most 1000, `request` as proto3 JSON with snake_case names and every field
  present). Not required by any screen in M1; generate its type with
  `openapi-typescript` if used.
