## What changed
`proto/trajectory/v1/config.proto` gets the message `StoreConfig`
(`table_prefix = 1`, `db_credentials_sealed = 2`) and the oneof members
`ConfigSet.store = 4` and `ConfigApplied.store = 8`, as in
`docs/design/persistence.md` > Data and API. `proto/README.md` > Config
payloads documents the prefix pattern, the AES-256-GCM sealing and the
write-only rule. `@albertoriorda95/trajectory-proto` is 0.2.0 with the new
types (the viz-web server's workspace dependency moves to 0.2.0 with it).

## What the others relied on (before → after)
- `ConfigSet` / `ConfigApplied` payload: only `propagator` (3 / 7) →
  `propagator` or `store` (4 / 8). Additions only: `buf breaking` passes; old
  decoders see an unknown field and ignore it.
- `@albertoriorda95/trajectory-proto`: 0.1.0 → 0.2.0 (adds `StoreConfig`,
  `StoreConfigSchema`, the `store` oneof case). Nothing removed.
- Generated code committed in a service: `services/api/src/trajectory/` is now
  one proto change behind (`services/api/scripts/generate-proto.sh --check`
  reports it; CI does not run it). api only reads the propagator
  `ConfigApplied`, so it works unchanged.
