## What changed
The CI `propagator` job starts NATS with JetStream and the streams of
`proto/nats/streams/` before ctest (`ci/nats-test.sh up`) and passes
`NATS_TEST_URL` to ctest. In `compose.yml` the propagator gets
`PROPAGATOR_CONFIG_PATH` and a named writable volume for it.

## What the others relied on (before → after)
- ctest in CI: no NATS → `NATS_TEST_URL=nats://127.0.0.1:4222`, a NATS 2.15.3
  server (same image and `deploy/nats/nats.conf` as compose, `max_payload`
  8 MiB) with `LAUNCHES`, `TRAJECTORIES`, `ERRORS`, `CONFIG` already created.
  The streams are shared by all tests of one run and are not emptied between
  tests: tests should use their own launch ids / consumers and must not
  delete the streams. Locally: `ci/nats-test.sh up` (or
  `docker compose up nats nats-init`), then `ci/nats-test.sh down`.
- Suggestion (backend decides): integration tests skip (not fail) when `NATS_TEST_URL` is unset, so
  `ctest` still runs on a machine without docker; CI always sets it.
- propagator in compose: no env var, nothing writable →
  `PROPAGATOR_CONFIG_PATH=/var/lib/propagator/config.json`; the folder is the
  `propagator-config` named volume, owned by uid 10001 (created in the image),
  so the temp file + rename in that folder works on the read-only root
  filesystem. Only that folder is writable: the temporary file must be in the
  same folder as the config file.
- The image builds and runs as before; the code does not read the variable
  yet (task 4 of `docs/design/propagation.md`).
