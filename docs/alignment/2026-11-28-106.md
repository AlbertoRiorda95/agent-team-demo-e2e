## What changed
The viz-web server now serves the live stream `GET /api/live` (SSE) and the
built UI at `/` (`@fastify/static`, from `services/viz-web/dist`), as in
docs/design/viewer.md (task 2). Contract: `services/viz-web/server/openapi.yaml`
0.2.0. It consumes `trajectories.computed` (stream `TRAJECTORIES`, ordered
consumer, deliver "last").

## What the others relied on (before → after)
- Routes: none under `/api/live` and `/` → `GET /api/live` (`text/event-stream`:
  `bus` events `{"nats":"connected"|"disconnected"}`, `trajectory` events with
  `id` = launch_id and the `TrajectoryComputed` in proto3 JSON, Last-Event-ID,
  `: keep-alive` every 15 s, slow clients closed above 32 MiB pending) and the
  built UI at `/` (404 while `services/viz-web/dist` is missing).
- `/healthz`: 503 while `launches.accepted` is not consumed → 503 while
  `launches.accepted` or `trajectories.computed` is not consumed (the
  `TRAJECTORIES` stream must exist: compose's `nats-init` already creates it).
- The UI folder is resolved relative to the server sources:
  `services/viz-web/server/src/main.ts` → `services/viz-web/dist/`. No new
  environment variable, no new port.
- New runtime dependency of the server: `@fastify/static` 10.1.12 (in the
  lockfile; the image's `npm ci -w services/viz-web/server` installs it).
